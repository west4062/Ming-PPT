# 생활기록부 평가문(세특) 작성 스킬

학생 자료 → 통합 Excel → 학생별 평가문(NLP) → 바이트 검증 → 검수용 HTML 까지를 잇는 5단계 파이프라인.
**평가문 문장은 전적으로 NLP(언어 능력)로 쓴다. 규칙 기반·템플릿 짜깁기로 문장을 찍어내지 않는다.** 스크립트는
바이트 계산, Excel/HTML 조립처럼 결정적이고 반복적인 일만 맡는다.

## 핵심 원칙 (먼저 새겨둘 것)
- **NLP 작성**: 평가문은 자료를 읽고 이해해 사람이 쓰듯 작성한다. "역량+근거"를 문자열 치환으로 조립하지 않는다.
- **자료에 충실**: 보고서·코드에서 실제로 확인되는 내용만 근거로 쓴다. 인터넷 검색·추측 금지. 학생이 쓴 문장을 그대로 베끼지 않는다.
- **단계별 체크포인트**: 별도 지시가 없으면 5단계를 차례로 밟고, 각 단계 끝에서 결과를 보여주며 진행 여부를 확인한다. 사용자를 친절히 안내한다.
- **분량은 python으로 측정**: 바이트 규칙은 한글 3 / 엔터 2 / 그 외 1. 눈대중하지 말고 `scripts/byte_count.py`로 잰다.
- **과목별 MEMORY**: 시작 시 해당 과목의 누적 지시를 읽고, 새 지시가 나오면 저장한다.

## 스킬 디렉토리
```
${CLAUDE_SKILL_DIR}/
├── SKILL.md
├── scripts/
│   ├── byte_count.py        # NEIS 바이트 계산(한글3/엔터2/그외1) · JSON 일괄 검수
│   ├── build_workbook.py    # students.json → 통합 검수 .xlsx (활동별 열 + 평가문 + 바이트/판정 색상)
│   ├── build_html.py        # students.json → 카드/표 토글 검수 HTML
│   └── build_gwagi.py       # students.json → 업로드 xlsx. NEIS 다운로드 파일을 --template로 주면
│                            #   학생코드·수업코드 보존하며 세특 칸만 채움(반/번호·이름 매칭). 없으면 평평한 새 양식
├── assets/
│   ├── default_prompt.txt   # 기본 프롬프트(인공지능 기초 평가문 양식) — 사용자 txt 없을 때 사용
│   └── 교과기초자료_양식.xlsx  # 교과세특 업로드 기준 양식(헤더: 학번·이름·교과세특·성적)
└── references/
    └── memory/
        ├── INDEX.md          # 과목별 MEMORY 운영 규칙 + 목록
        ├── <과목>.md          # 과목별 누적 지시(+ 맞춤 프롬프트 파일 포인터)
        └── <과목>.prompt.txt  # 과목 맞춤 프롬프트(기본 프롬프트를 기초 정보에 맞게 적응한 것) — 2단계에서 재사용
```
경로 참조 시 `${CLAUDE_SKILL_DIR}`는 이 스킬 폴더(`E:\presentation\.claude\skills\saenggibu-writer`)다.

## 중간 데이터 형식: `students.json`
모든 스크립트가 공유하는 단일 표현. 자료 정리(3단계)에서 만들고, 평가문(4단계)에서 채운다.
```json
{
  "subject": "인공지능 기초",
  "students": [
    {
      "번호": "10101", "이름": "홍길동", "성적": 92,
      "제약사항": "장기결석으로 서비스개발 보고서 없음",
      "활동": {
        "이미지분류프로젝트": "데이터셋 불균형을 발견하고 증강으로 보완…",
        "AI서비스개발": "노인 대상 음성 비서를 기획…",
        "자기평가": "처음엔 정확도가 낮아 좌절했지만…"
      },
      "목표바이트": "1400~1500",
      "평가문": "",
      "바이트수": 0
    }
  ]
}
```
- `활동`의 키(=활동명)는 자유롭게 늘릴 수 있고, Excel에서 그대로 열이 된다.
- `목표바이트`는 프롬프트의 분량 규칙 + 성적으로 4단계에서 정한다(스크립트가 강제하지 않음 → 프롬프트가 바뀌어도 동작).
- 작업 산출물은 작업 폴더(예: `<과목>_생활기록부/`)에 두고, 스킬 폴더 안에는 쓰지 않는다.

## 1단계 — 기초 정보 수집 (+ 과목 MEMORY 로드)
평가문을 쓰기 전에 꼭 필요한 것만 간단히 묻는다. 이미 답이 주어졌으면 다시 묻지 않는다.
1. **과목명** (예: 인공지능 기초, 정보, 프로그래밍)
2. **제공 자료**: 종류와 경로. 형태가 ① 이미 정리된 CSV/Excel인지 ② 학생별 개별 파일(pdf/hwpx/xlsx 등)인지.
3. **프롬프트**: 사용자 txt 경로가 있는지(`@C:\...\prompt.txt`). 없으면 `assets/default_prompt.txt`를 기본값으로 쓴다고 안내.
4. **성적/제약사항** 자료가 따로 있는지(분량 조절·자료 누락 처리에 쓰임).
5. **NEIS 업로드 양식**(권장): NEIS '과목별세부능력및특기사항'에서 내려받은 엑셀 파일이 있는지 묻는다. 있으면 5단계에서 이 파일을 그대로 채워 NEIS에 바로 올릴 수 있다(학생개인번호·과목코드 등 메타데이터 보존). 파일명 예: `2026_1학기_1학년_1_정보_과목세특_1.xlsx`. 경로를 받으면 `<과목>.md` 메모에 적어 둔다.
6. **산출물 위치**(미지정 시 `<과목>_생활기록부/` 제안).

그 다음 `references/memory/<과목>.md`를 읽는다(없으면 INDEX.md의 규칙대로 새로 만들 준비). 거기 누적된 지시를 이후 단계에 반영한다.
정리한 기초 정보를 사용자에게 한 번 요약해 보여주고 다음 단계로 넘어간다.

## 2단계 — 프롬프트 준비 (사용자 txt → 과목 저장 프롬프트 → 기본 프롬프트 적응)
프롬프트는 고정 양식이 아니다. 출처를 다음 **우선순위**로 정한다.

1. **사용자가 txt 경로를 준 경우** → 그 파일을 Read로 읽어 사용한다. (이 과목에서 계속 쓸 양식이면 아래 3번처럼 `<과목>.prompt.txt`로 저장해 둔다)
2. **없고, `references/memory/<과목>.prompt.txt`가 있으면** → 이전에 이 과목에 맞게 적응해 저장해 둔 맞춤 프롬프트를 그대로 사용한다(매번 다시 만들지 않는다).
3. **둘 다 없으면** → `assets/default_prompt.txt`를 **1단계 기초 정보에 맞게 적응**한 뒤 저장해 쓴다:
   - '사용할 학생 자료' 목록을 사용자가 실제로 제공한 자료로 채운다(기본 프롬프트는 이 칸이 비어 있음).
   - 목적·작성자의 **과목명**을 실제 과목으로 바꾼다.
   - **분량·성적 연동 규칙**을 사용자가 정한 기준으로 조정한다(사용자가 따로 정하지 않았으면 기본값 유지).
   - 역량 분류·문체·어미·금지사항 등 **핵심 규칙은 유지**한다.
   - 적응한 프롬프트를 사용자에게 보여 확인받고, **`references/memory/<과목>.prompt.txt`로 저장**한다(다음부터 2번 경로로 자동 재사용). `<과목>.md`에는 이 프롬프트 파일을 가리키는 한 줄을 둔다.

- 어느 경로든, 사용할 프롬프트에서 **추출**할 것을 요약해 확인받는다: ① 평가 관점/역량 분류 ② 분량·바이트 규칙(성적 연동 포함) ③ 문체·어미 규칙 ④ 금지사항 ⑤ 사용할 자료 목록.
- **이번 프롬프트의 규칙을 그대로 따른다**(스킬에 박힌 가정으로 덮어쓰지 않는다). 과목 MEMORY의 누적 지시가 프롬프트에 반영될 성격이면 `<과목>.prompt.txt`도 함께 갱신한다.

## 3단계 — 학생 자료 처리 → 통합 Excel
목표: 흩어진 자료를 `students.json` 한 곳에 모으고 `build_workbook.py`로 Excel을 만든다.

**(A) 이미 정리된 CSV/Excel을 받은 경우** — 별도 가공 없이 활용한다. `xlsx` 스킬로 열어 열 구조만 확인하고, 학생/활동 매핑이 명확하면 그대로 `students.json`으로 옮긴다.

**(B) 학생별 개별 자료인 경우** — 자료를 읽어 학생별로 활동 내용을 추출한다.
- **pdf**(보고서): `Read` 도구로 직접 읽는다(이미지·표 포함). 보고서의 답변/결과/회고를 활동별로 요약해 담되, **문장을 그대로 옮기지 말고 사실만 추출**한다.
- **hwpx/hwp**: `hwpx` 스킬(`text_extract.py` 등)로 텍스트를 뽑는다.
- **xlsx**(자기평가 등): `xlsx` 스킬로 읽어 학생-항목을 매핑한다.
- 자료가 없는 항목(예: 서비스개발 보고서 미제출)은 비워 두고 `제약사항`에 메모한다.
- 성적·제약사항 등 별도 정보가 있으면 해당 학생에 합친다.

추출 결과를 `students.json`으로 저장한 뒤:
```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_workbook.py" students.json 결과.xlsx
```
Excel을 사용자에게 보여주고(또는 경로 안내) "자료 정리가 맞는지" 확인받은 다음 4단계로 간다. **이 시점에 평가문 열은 비어 있다.**

> 자료 추출은 학생 수가 많으면 병렬 서브에이전트로 나눠도 되지만, **추출(사실 정리)과 평가문 작성(NLP 서술)은 분리**한다. 추출 단계에서 미리 평가문을 쓰지 않는다.

## 4단계 — 학생별 평가문 작성·저장 (NLP)
여기가 스킬의 핵심. **자료 + 프롬프트를 근거로, 한 명 한 명 실제로 읽고 판단해 작성한다.**

**배치 진행 방식** — 사용자에게 한 번 묻는다: "몇 명씩 작성하고 확인할까요? (예: 5명씩 / 한 반씩 / 전체 일괄)". 답에 맞춰
- 소배치면 그 인원만 쓰고 보여주며 확인 → 다음 배치, 를 반복.
- 전체 일괄이면 모두 쓴 뒤 한꺼번에 검수로 넘긴다.
첫 배치(또는 첫 1~2명)는 **문체·근거 선정 방식의 기준점**이 되므로, 사용자 승인을 받고 나머지에 같은 기준을 적용하면 일관성이 좋아진다.

**한 학생 작성 절차** (프롬프트의 단계 지시가 있으면 그것을 우선):
1. 자료에서 의미 있는 역량을 프롬프트 기준으로 1~2개 선정(전반적 인물평은 역량 선정에 참고만, 글의 재료로는 쓰지 않음).
2. 역량마다 **하나의 강한 사례**를 근거로 고른다. 어려움 극복·독서 연계가 있으면 그 과정을 살린다.
3. 프롬프트의 문체/어미/금지사항/분량을 지키며 한 문단으로 서술. 첫 문장만 역량을 요약하고, 이후는 근거만 제시한다(“~역량을 보여줌” 식 메타표현 자제). 변수명·코드 같은 과한 디테일, 동일 어휘 반복, 부정 평가는 피한다.
4. **분량 맞추기**: 성적으로 `목표바이트`를 정하고(프롬프트 규칙대로), 작성 후 바이트를 잰다.
   ```bash
   python "${CLAUDE_SKILL_DIR}/scripts/byte_count.py" "작성한 평가문"
   ```
   목표를 벗어나면 근거의 밀도를 조절해 **다시 쓴다**(자르거나 늘리는 게 아니라 서술을 다듬어 맞춘다).
5. `students.json`의 해당 학생 `평가문`·`목표바이트`를 채운다.

배치가 끝나면 전체 바이트를 일괄 검수:
```bash
python "${CLAUDE_SKILL_DIR}/scripts/byte_count.py" --json students.json --write
```
초과/미달 학생을 표로 확인하고 보정한 뒤, Excel을 갱신한다:
```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_workbook.py" students.json 결과.xlsx
```

## 5단계 — HTML 검수본 + 교과기초자료 양식
두 가지를 함께 만든다. (검수는 사람이 보기 쉽게, 업로드는 학교 양식에 맞게)

**(1) 검수용 HTML** — 학생별 평가문을 보기 쉽게 카드/표 토글로.
```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_html.py" students.json 결과.html
```
- **카드형**: 학생별로 평가문·바이트 배지(적정/초과/미달)·활동자료(접기)를 본다 → 개별 검수.
- **표형**: 전체를 한 표에서 정렬/검색 → 한눈에 비교. 상단 토글·검색으로 전환.

**(2) 교과세특 업로드 양식 xlsx** — `build_gwagi.py`는 `--template`을 보고 **두 모드를 자동**으로 고른다.

**(2-A) NEIS 채우기 모드 (권장 · 1단계에서 NEIS 다운로드 파일을 받았을 때)**
NEIS '과목별세부능력및특기사항'에서 내려받은 엑셀은 학생개인번호(학생코드)·과목코드(수업코드)·반/번호·성명이 이미 채워져 있고 '세부능력 및 특기사항' 칸만 비어 있다. 이 파일을 `--template`로 주면 **원본을 그대로 보존**하면서 세특 칸만 채워, 그대로 NEIS에 다시 업로드할 수 있다.
```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_gwagi.py" students.json 결과_NEIS업로드.xlsx \
  --template "C:/.../2026_1학기_1학년_1_정보_과목세특_1.xlsx"
```
- 매칭 우선순위: **① 반/번호 완전일치 → ② 이름 → ③ (반 없는 양식일 때만) 번호**. 한 학생이 두 행에 들어가지 않게 막는다.
- `students.json`의 `번호`는 `10112`(학년반번 묶음)·`1/12`·`12` 형식을 모두 인식한다. 별도 `반` 필드가 있으면 우선 사용.
- 실행 후 **매칭 리포트**를 반드시 확인한다: ⚠양식에는 있으나 못 찾은 행 / ⚠students.json에는 있으나 안 들어간 학생 / 이름 중복 보류 목록. 미매칭이 있으면 `번호`·`이름`을 맞춰 다시 돌린다.
- 세특 열·반/번호 열은 헤더 이름(`세부능력 및 특기사항`, `반/번호` 등)으로 자동 탐지하므로 NEIS 양식이 바뀌어도 대개 동작한다.

**(2-B) 새로 만들기 모드 (평평한 양식)** — NEIS 파일이 없을 때.
```bash
python "${CLAUDE_SKILL_DIR}/scripts/build_gwagi.py" students.json 교과기초자료.xlsx \
  --template "${CLAUDE_SKILL_DIR}/assets/교과기초자료_양식.xlsx"
```
- 기본 헤더: **학번 · 이름 · 교과세특 · 성적** (한 행 = 학생 한 명, 교과세특 칸 = 평가문).
- `--template`에 헤더만 있는 학교 양식을 주면 그 1행 헤더(이름·순서)를 따르고 별칭표로 값을 채운다. 생략하면 기본 4열.
- 모드는 자동 판별된다(학생코드·수업코드 등 메타 헤더가 있거나, 반/번호 칸 + 데이터 2행 이상이면 NEIS 채우기). 강제하려면 `--mode neis|build|auto`.

산출물(`결과.xlsx`(검수), `결과.html`(검수), 업로드 xlsx(NEIS 채움 또는 새 양식), `students.json`) 위치를 안내하고 마무리한다.

## 과목별 MEMORY 운영
- 시작 시 `references/memory/<과목>.md`(누적 지시)와 `references/memory/<과목>.prompt.txt`(맞춤 프롬프트, 있으면)를 읽어 반영한다.
- **맞춤 프롬프트 관리**: 2단계에서 기본 프롬프트를 적응해 만든 `<과목>.prompt.txt`를 과목별로 보관·재사용한다. 같은 과목을 다시 작업하면 이 파일을 우선 사용한다. 자료 구성·분량 기준이 바뀌면 이 파일을 갱신한다.
- 사용자가 **재사용할 지시**("앞으로 이 과목은 ~", "독서 연계를 꼭 넣어줘" 등)를 주면 `<과목>.md`에 한 줄로 추가하고, 프롬프트에 반영될 성격이면 `<과목>.prompt.txt`도 고친 뒤, `INDEX.md` 목록도 갱신한다. 무엇을 저장했는지 사용자에게 알린다.
- 일회성 요청은 저장하지 않는다. 규칙은 `references/memory/INDEX.md` 참조.
